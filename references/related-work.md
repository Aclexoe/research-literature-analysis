# Related Work / Literature Review 句式库

> 用法：Related Work 必须按路线组织，体现演化 + 区别 + 局限 + 你的位置。
> 禁止按论文 1、2、3 罗列，禁止流水账。

## 路线组织句式

- 第一类研究采用 ___（代表：Author et al., Year），解决了 ___，但仍存在 ___ 局限。
- 在此基础上，第二类研究引入 ___，代表作 ___，相比前代改进了 ___，但引入了 ___ 新问题。
- 当前主流已演进为 ___，然而在 ___ 条件下仍不稳定（证据：___）。
- 本文工作位于 ___ 路线，与 ___ 最接近，区别在于 ___，针对其 ___ 局限做了 ___ 改进。

## 演进链句式

```
问题 -> 第一代方法 -> 暴露什么缺陷 -> 第二代为何出现 -> 解决部分+引入新问题 -> 当前状态
```

- 传统 ML（依赖人工特征） -> CNN（自动特征，但长依赖弱） -> Transformer（长依赖强，但数据/算力贵） -> 预训练/基础模型
- 按需替换为本领域实际路线（如：统计 / 规则 vs 数据驱动 / 机理 / PINN / 混合）。

## Review 结构

背景 -> 分类 -> 各类方法 -> 比较 -> 共识 -> 分歧 -> 局限 -> Gap -> 未来

## 引用规范

- 有作者年份用 `(Author et al., Year)`，用户用数字则跟随 `[1]`。
- 重要判断必须可追溯；无信息写 `论文未明确报告`。
- 跨数据集不比数值，不忽略年份和 baseline 公平性排名。

## 创新定位检查

- 是否已有类似工作？区别是换模型还是换问题？
- 是否解决已知 limitation？能否被实验验证？
- 属于数据 / 方法 / 理论 / 任务 / 应用 / 实验 / 系统哪类创新？
- 只换模型 + 同数据同指标 = 弱创新，需论证新场景特有缺陷。
